# 安全與隱私防護策略 (Security & Privacy)

## 1. 資料敏感度分級 (Data Classification)

系統將個人與企業資訊分為三級（L1 / L2 / L3）：

| 級別 | 類別範例 | 預設行為 | 儲存方式 |
|---|---|---|---|
| **L1：常用公開資料** | 公司名、統編、登記地址、電話、Email、業務描述 | 自動帶入 | 本地一般 JSON / .env |
| **L2：證件個人隱私** | 身分證字號、護照號碼、出生年月日、個人戶籍 | 自動帶入前確認 / 本地加密 | 本地 AES-256 加密 Vault |
| **L3：高敏感金流資訊** | 信用卡號、CVV/CVC、有效期限、銀行網銀帳密 | 絕不自動送出 / 需 2FA 確認 | 本地 OS Keyring / 記憶體即用即銷毀 |

## 2. 本地安全金庫 (Zero-Knowledge Local Vault)

### 2.1 加密機制
* **加密演算法**：AES-256-GCM（同時確保保密性與完整性認證）。
* **金鑰來源 (Key Derivation)**：
  * 方案 A：使用系統原生憑證庫（macOS Keychain / Windows Credential Manager / Linux SecretService）。
  * 方案 B：由使用者輸入主密碼（Master Password）透過 Argon2id / PBKDF2 衍生加密金鑰。
* **零留存承諾**：雲端中繼伺服器永遠接觸不到金鑰，亦不儲存任何解密後內容。
* **隨時銷毀**：支援 CLI `form-filler vault purge` 一鍵徹底抹除本機檔案。

## 3. 雲端與 LINE 整合資安機制

### 3.1 為什麼資料不放雲端？
* 傳統雲端表單填寫機器人最大的資安破口在於「將所有使用者的身分證與信用卡存於集中式資料庫」，一旦伺服器被攻擊即造成嚴重外洩。
* **本系統採「端點執行（Local-First Execution）」**：雲端只轉發指令（`URL: https://...`），所有解密與填表過程只在使用者本機記憶體進行。

### 3.2 如果在無本機的「純雲端環境」運作？（備用雲端模式）
若使用者出門在外需使用純雲端無頭瀏覽器，必須遵守以下鐵律：
1. **端到端加密（E2EE）**：使用者透過 LINE LIFF Web 端以一次性公鑰加密後傳送。
2. **零持久化（Zero-Persistence）**：敏感資料僅留存於運行中的微型 Container 記憶體中，填寫完成後立即呼叫 `zeroize()` 抹除並銷毀 Container。
3. **敏感欄位遮蔽（Masking）**：LINE 上回傳的預覽截圖自動模糊處理身分證、信用卡等特定區域。
